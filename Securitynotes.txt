======================What is the purpose of generating token in Jwtutil and for what token will be generated?=====================================
The purpose of generating a token in JwtUtil is to allow a user to access protected APIs after successfully logging in, 
without entering their username and password for every request.
---------------For whom is the token generated?
A JWT token is generated for a user who successfully logs in.
Step 1: User registers
Username: chandu, Password: ********
Step 2: User logs in
Spring Boot checks the username and password against the stored user credentials.
Step 3: JWT token is generated
If the credentials are valid, the backend creates a token for that user.
Step 4: User accesses protected APIs
The client sends the token with each protected request. The backend validates it before allowing access.
API	Purpose
POST /register	Create an account
POST /login	Verify credentials and obtain a token
GET /me	Get the logged-in user's profile
Imagine the user logs in successfully.
The backend generates a JWT such as:
eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJjaGFuZHUifQ.signature
The backend sends it to the frontend. The frontend can then send it when requesting the user's profile:
GET /me
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
The backend validates the token and identifies the user associated with it.

public String generateToken(String email, String role) {
        Date now = new Date();
        Date expiry = new Date(now.getTime() + expirationMs);
        return Jwts.builder()
                .subject(email)
                .claim("role", role)
                .issuedAt(now)
                .expiration(expiry)
                .signWith(key)
                .compact();
    }
The above method is token creation for the user who successfully logs in

Date: why do we need it? The JWT should record when it was created. We also use this time to calculate when it expires.
Expiration time: current time: 11:00 am + validation duration: 1hour = > Expiration time: 12:00 pm after 12 my token will expire
          .subject = The subject is a standard JWT claim that identifies the principal the token represents.
          Later, your backend can extract this subject to determine which user the token represents.
          .signWith(key) = This signs the JWT using the secret key you created in your JwtUtil constructor.
                            The signature helps the backend detect whether the token has been altered.
                            For example, if someone changes the token's role from USER to ADMIN, the original signature will no longer match the modified token.

Example: Imagine you log in to your Resume Analyzer application at 10:00 AM, and the JWT expires after one hour.
          10:00 AM — Login successful
          Your username and password are verified, and the backend generates a JWT.
          10:30 AM — Using the application
          Your requests include the JWT. The backend validates it and allows access if you have the necessary permissions.
          11:00 AM — Token expires
          The backend rejects the expired token when it is used for a protected request.
          What happens next?
                  - Without a refresh-token mechanism: the user generally needs to log in again.
                  - With a valid refresh token: the application may obtain a new access token without asking the user to enter their password again.
